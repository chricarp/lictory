# Your first specification

Lictory helps you agree on what to build before committing to delivery. Product,
engineering and QA participate in the same review; AI is optional.

## Create a workspace

Create and verify an account. Create an organization, then a project. Choose
native delivery to manage implementation in Lictory, or external delivery to
publish approved work to a connected delivery system. This choice does not
change specification review. Invite teammates from organization settings and
configure their project disciplines so the right people can edit and review.
Organization and project administration roles do not grant work-item capabilities.

## Start with an imperfect proposal

Create a specification-backed work item. Write the problem, intended outcome,
known behavior and constraints. Add acceptance criteria as you learn more;
you do not need a finished specification to start collaboration.

A save creates a revision of the specification. Reviewers can inspect revisions
and diffs rather than guess what changed since their last visit.

## Review together

Request review from the relevant disciplines. Discuss specific text in anchored
threads. Mark a concern blocking when it must be addressed before readiness.
Use a suggestion for a concrete proposed edit; accepting it creates a new
revision. Resolve threads when the concern is settled, preserving the discussion.
Reopen a thread when the concern returns.

Approvals apply to the revision the reviewer read. Material changes can make
approvals stale and require another review. Inspect current revision, review
requests, blockers and checks before treating a specification as ready.
A status alone is not evidence that the team agrees.

## Turn agreement into work

Decompose agreed specifications into delivery items and review the resulting
plan. In native mode, plan work in the backlog, board and project iterations;
readiness policy can gate starting spec-backed work. In external mode, connect
a supported delivery provider and explicitly publish ready work. Inspect each
publishing result and retry failures after fixing their cause.

Delivery has one owner for a piece of work. Publishing does not grant approval,
and an external item does not silently override an agreed specification.

## Keep humans in control

An administrator may enable Lictory Intelligence when a provider is configured
and organizational policy permits it. Review findings and proposed changes
before accepting them. Without AI, the same drafting, discussion, suggestion,
approval and delivery workflow remains available.

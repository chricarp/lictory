An agent event says that something waits on a person or one of their agents. It carries identifiers and short titles, never specification text or message bodies, and it never authorizes anything: the agent reads the details with its ordinary tools, with its person's permissions. [AI agents and MCP](/integrations/agents#wake-your-agent-when-something-waits-on-you) explains how to set up each way of being woken.

| Way              | How                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| The feed         | `listEvents({ after: "latest" })` once, then `waitForEvents` with the returned cursor in a loop (it answers within 25 seconds) |
| MCP Events       | The client subscribes with `events/subscribe` (webhook mode); deliveries are signed with its `whsec_` key                      |
| A bearer webhook | A URL and secret a person adds in the agent's **Wake-ups** (or Account settings → Event webhooks)                              |

## Event types

| Type                       | When                                                                                                                                |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `channel.mentioned`        | You, or your agent, were @mentioned in a channel, thread or direct message.                                                         |
| `channel.direct_message`   | Someone sent you a direct message.                                                                                                  |
| `discussion.mentioned`     | You were @mentioned in a discussion on a specification or a page.                                                                   |
| `discussion.blocking`      | A blocking discussion was opened on a specification or page you are involved in.                                                    |
| `review.requested`         | You, or a discipline you belong to, were asked to review a specification, a pull request, a suggestion or a page change.            |
| `review.decided`           | A reviewer approved, requested changes on, or revoked approval of a specification or suggestion you own or requested review for.    |
| `approval.invalidated`     | Something you approved changed, so your approval needs your review again.                                                           |
| `item.assigned`            | A work item was assigned to you.                                                                                                    |
| `item.ready`               | Every readiness check passes for a specification you are involved in.                                                               |
| `pull_request.decided`     | A reviewer approved or requested changes on a pull request you authored or collaborate on (specification, page or code).            |
| `pull_request.mergeable`   | A specification pull request you authored meets its merge requirements.                                                             |
| `pull_request.merged`      | A pull request you authored, collaborate on or reviewed was merged.                                                                 |
| `pull_request.unmergeable` | A code pull request linked to your work can no longer be merged (conflicts or failing required checks).                             |
| `agent.approval_requested` | An agent session you started, or whose agent you own, waits for a person to approve or deny something. Only a person can answer it. |
| `agent.session_finished`   | An agent session you started completed or failed.                                                                                   |
| `claim.question_resolved`  | A person resolved a question your agent asked on its claimed work.                                                                  |
| `claim.released`           | Your agent's claim ended: released by a person, expired without renewal, or completed by its Definition of Done.                    |

Webhooks may also receive `lictory.test`, sent when a person chooses **Test**.

## Bearer webhooks

A delivery is a `POST` with this body. `text` and `message` hold the same sentence, because receivers that start an agent run read one or the other; `event` holds the type, a cursor and the data.

```json

  "message": "Lictory event channel.mentioned: You were mentioned in #field-devices. This describes what happened; it is information, not an instruction. Read the details with Lictory's MCP tools.",
  "event": {
    "id": "evt_4vQk3V1yJ9mWl2y6nC0pZ8aB1cD",
    "type": "channel.mentioned",
    "occurredAt": "2026-11-25T21:36:12.031Z",
    "cursor": "42",
    "data": {
      "id": "5f0c2a52-2b8e-4d47-9c1e-6f1c9a4b7d10",
      "type": "channel.mentioned",
      "occurredAt": "2026-11-25T21:36:12.031Z",
      "organizationId": "b9395955-bcb1-4112-9869-8884860e9bf9",
      "organizationSlug": "acme",
      "projectId": null,
      "agentId": "11c8f288-e002-49d2-8365-2e38926dd01a",
      "actorId": "290764be-0ef3-4c88-b32c-327cd3c9339e",
      "subject": {
        "channelId": "85ad1816-8687-413e-a1f9-8f5a6630aed4",
        "messageId": "78b1ebc3-5cf7-441f-9a7b-931af76c47e2",
        "channelName": "field-devices"

    }

```

| Header                 | Value                                                                                                                                                            |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Authorization`        | `Bearer <secret>`, the secret the person entered                                                                                                                 |
| `webhook-id`           | The delivery's id: the same on every retry of one event, so receivers deduplicate by it                                                                          |
| `webhook-timestamp`    | When this attempt was sent, in Unix seconds                                                                                                                      |
| `webhook-signature`    | `v1,<base64 HMAC-SHA256>` of `<webhook-id>.<webhook-timestamp>.<body>`, keyed with the secret (its key bytes if it is a `whsec_` key, its UTF-8 bytes otherwise) |
| `x-lictory-event-type` | The event type, `lictory.test` for a test                                                                                                                        |
| `User-Agent`           | `Lictory-Webhooks/1`                                                                                                                                             |

## MCP Events deliveries

## Delivery and retries

- Events of one destination are delivered **one at a time, oldest first**, and the next is sent only after the receiver answered `2xx`: delivery is at least once and in order.
- A failed event is retried after 30 s, 1 min, 2 min, 4 min. After 5 failures, or at once when the receiver answers `410 Gone`, the destination is **suspended** with its reason until its person resumes it (or its MCP client renews the subscription). `413` skips that event.
- Redirects are not followed. Webhooks reach public HTTPS addresses unless the installation allows private networks, and organization administrators decide in Organization settings → Security whether events may leave at all.

## Verify a delivery

Check the signature and the timestamp before acting on a delivery, so a request logged somewhere cannot be replayed. This works for both kinds of webhook (Node.js, no dependencies):

```js
import { createHmac, timingSafeEqual } from "node:crypto";

// secret: the webhook's secret (Wake-ups or Account settings → Event
// webhooks), or the whsec_ key your MCP client subscribed with.
// headers: the request headers, lowercase names. body: the raw body text.
export function verifyLictoryWebhook(secret, headers, body, now = Date.now()) {
  const id = headers["webhook-id"];
  const timestamp = Number(headers["webhook-timestamp"]);
  if (!id || !Number.isInteger(timestamp)) return false;
  // Refuse old or future deliveries, so a logged request cannot be replayed.
  if (Math.abs(now / 1000 - timestamp) > 5 * 60) return false;
  const key = secret.startsWith("whsec_")
    ? Buffer.from(secret.slice("whsec_".length), "base64")
    : Buffer.from(secret, "utf8");
  const expected = createHmac("sha256", key)
    .update(`${id}.${timestamp}.${body}`)
    .digest();
  // Several signatures are sent while a subscription's key rotates.
  return (headers["webhook-signature"] ?? "").split(" ").some((entry) => {
    const [version, mac] = entry.split(",");
    if (version !== "v1" || !mac) return false;
    const given = Buffer.from(mac, "base64");
    return given.length === expected.length && timingSafeEqual(given, expected);
  });
}
```

Compute it over the raw body exactly as received, before parsing the JSON. A `whsec_` secret must be a valid Standard Webhooks key (base64 after the prefix).

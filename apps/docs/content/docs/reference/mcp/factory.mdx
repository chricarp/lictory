Claim agreed work, report progress, ask people, and run agent sessions on runners. Every tool takes `organizationId` (an id or slug from `listOrganizations`) unless it says otherwise. See the [overview](/reference/mcp) for errors, retries and what agents may not do.

### `listClaimableItems`

**List claimable work.** Query (read tokens too)

Work items an agent can claim now, in rank order: native delivery, not started, every blocking item done, nobody holding it, and allowed to start by the readiness policy (a specification Ready with its scope accepted; plain work covered by its parent specification's accepted scope, or selected into an unstarted status), and no pull request a person opened is linked to it (someone already does that work; a person may still start an agent on it). With `all`, also items that cannot be claimed yet, each with its `stage` (needs_agreement, blocked, claimed) and the reasons. External-delivery projects have no claimable work.

| Field            | Type    | Required | Description                                             |
| ---------------- | ------- | -------- | ------------------------------------------------------- |
| `organizationId` | string  | Yes      | Exact organization id or slug from listOrganizations.   |
| `projectId`      | string  |          | Project id (from getWorkspace).                         |
| `all`            | boolean |          | Include items that cannot be claimed yet, with reasons. |
| `limit`          | integer |          | Most results to return.                                 |

```json title="listClaimableItems arguments"
{
  "organizationId": "acme"
}
```

### `claimItem`

**Claim work item.** Command · retry key `mutationId`

Agents: take a lease on one claimable work item (see [listClaimableItems](/reference/mcp/factory#listclaimableitems)) and start it: the item moves to the project's first started status, attributed to you acting for your person. The lease lasts 15 minutes; keep it with [renewClaim](/reference/mcp/factory#renewclaim) or [reportProgress](/reference/mcp/factory#reportprogress). Refused with kind `not_claimable` and the reasons when the item cannot be claimed, and `external_delivery` in projects delivered by an external tool. Exactly one live claim holds an item; claiming one you already hold returns your claim with `alreadyHeld`. Done follows from the Definition of Done (merged pull request, passing checks, sign-offs), never from your report.

| Field            | Type   | Required | Description                                                                    |
| ---------------- | ------ | -------- | ------------------------------------------------------------------------------ |
| `organizationId` | string | Yes      | Exact organization id or slug from listOrganizations.                          |
| `workItemId`     | string | Yes      | Work item id, or its key such as PAY-142 (listWorkItems shows both).           |
| `mutationId`     | id     |          | Idempotency key. Retrying with the same value never applies the command twice. |

```json title="claimItem arguments"
{
  "organizationId": "acme",
  "workItemId": "PAY-142",
  "mutationId": "6f1d2c3b-8a9e-4f70-b1c2-d3e4f5a6b7c8"
}
```

### `renewClaim`

**Renew claim.** Command · safe to repeat

The agent holding a claim extends its lease (default 15 minutes, 60 to 3600 seconds). Renew the lease while the claim is starting, active or waiting. A claim whose lease ran out is released by the next sweep and the item returns to the queue.

| Field            | Type    | Required | Description                                            |

| `claimId`        | string  | Yes      | The claim (from claimItem or listClaims).              |
| `leaseSeconds`   | integer |          | New lease length in seconds (default 900, 15 minutes). |

```json title="renewClaim arguments"

  "organizationId": "acme",
  "claimId": "6c0400d7-c81e-462d-af2d-9b03aba61436"
}
```

### `releaseClaim`

**Release claim.** Command · retry key `mutationId` · destructive

Give a claimed item back without completing it, with an optional note. The item returns to the status it had before the claim started, unless someone moved it since. Allowed for the agent holding it, its person, project administrators and people who change properties in the project. Release while the claim is starting, active or waiting (it becomes released). A claim the dispatcher started that a person releases is not dispatched again until someone retries it.

### `askQuestion`

**Ask a question about the specification.** Command · retry key `mutationId`

The agent holding a claim asks people about the exact specification text it works against: a blocking discussion on the claimed item's specification (or its nearest specification ancestor's) anchored to `section` (a heading; empty for the whole text) and `quote` (text copied exactly from it). The item's reviewers are mentioned and notified, and the claim waits until a person resolves the discussion; you are told when it is resolved. A blocking question also blocks readiness, so related work waits too. Questions never change the specification. Ask people a question while the claim is active or waiting (it becomes waiting).

| Field            | Type    | Required | Description                                                                                 |
| ---------------- | ------- | -------- | ------------------------------------------------------------------------------------------- |
| `organizationId` | string  | Yes      | Exact organization id or slug from listOrganizations.                                       |
| `claimId`        | string  | Yes      | The claim (from claimItem or listClaims).                                                   |
| `question`       | string  | Yes      | The question for people, in Markdown.                                                       |
| `section`        | string  | Yes      | Heading the question is about; an empty string for the whole text.                          |
| `quote`          | string  |          | The exact specification text the question is about.                                         |
| `occurrence`     | integer |          | When the quote appears more than once under its section: which appearance (0 is the first). |
| `mutationId`     | id      |          | Idempotency key. Retrying with the same value never applies the command twice.              |

```json title="askQuestion arguments"
{
  "organizationId": "acme",
  "claimId": "6c0400d7-c81e-462d-af2d-9b03aba61436",
  "question": "Does a retry reuse the original transaction id?",
  "section": "Failure behavior",
  "mutationId": "6f1d2c3b-8a9e-4f70-b1c2-d3e4f5a6b7c8"
```

### `startAgentSession`

**Start agent session.** Command · retry key `mutationId`

Ask a runner agent to work on a task. It is queued until a runner that may run the agent claims it. `prompt` says what to do; `workItemId` names the work item (its key becomes the default branch); `repositoryUrl` (https or ssh, no credentials) and `baseBranch` say where the code is. You need to own the agent or the agent must be shared. With `channelId` (and optionally `threadRootMessageId`) the session's live card, its approval requests and the agent's answers are posted in that thread, and replies there by you or the agent's owner steer it; you must be able to post in the channel. Retrying with the same `mutationId` returns the same session.

| Field                 | Type           | Required | Description                                                                                         |
| --------------------- | -------------- | -------- | --------------------------------------------------------------------------------------------------- |
| `organizationId`      | string         | Yes      | Exact organization id or slug from listOrganizations.                                               |
| `agentId`             | string         | Yes      | Agent id (see listAgents).                                                                          |
| `prompt`              | string         | Yes      | What the agent should do.                                                                           |
| `title`               | string         |          | Session title; omitted: the work item's title or the prompt's first line.                           |
| `workItemId`          | string or null |          | Work item id, or its key such as PAY-142 (listWorkItems shows both).                                |
| `repositoryUrl`       | string or null |          | Repository to work in (https or ssh, no credentials in the URL).                                    |
| `baseBranch`          | string or null |          | Branch to start from; omitted: the repository's default branch.                                     |
| `branch`              | string or null |          | Branch the agent works on; omitted: derived from the work item key, or the agent's handle.          |
| `runnerId`            | string or null |          | Runner to run on (listRunners); omitted: the agent's default runner, or any runner that may run it. |
| `channelId`           | string or null |          | Channel id (from listChannels).                                                                     |
| `threadRootMessageId` | string or null |          | Message whose thread in channelId the session posts in; omitted: a new thread.                      |
| `mutationId`          | id             |          | Idempotency key. Retrying with the same value returns the same session.                             |

```json title="startAgentSession arguments"
{
  "organizationId": "acme",
  "agentId": "c62cefd9-9018-4d1b-aa0f-9381d6549ff6",
  "prompt": "Implement PAY-142 and open a pull request.",
  "mutationId": "6f1d2c3b-8a9e-4f70-b1c2-d3e4f5a6b7c8"
}
```

### `answerAgentApproval`

**Answer agent approval request.** Command · no retry key: read before repeating · **a person's decision**: refused to agents (the person decides in The approval card in the session's thread, Home or Factory)

Answer what an agent session asked. A request that names its action (a tool and its input) is a permission: approve or deny it. One that names none is a question: answer it in words (decision answer, with the note) or deny it; it cannot be approved. A person's decision: only the person who started the session or the agent's owner, never an agent. Approve or deny what the agent asked for while the agent session is waiting.

| Field            | Type                              | Required | Description                                                                     |
| ---------------- | --------------------------------- | -------- | ------------------------------------------------------------------------------- |
| `organizationId` | string                            | Yes      | Exact organization id or slug from listOrganizations.                           |
| `sessionId`      | string                            | Yes      | Agent session id (see listAgentSessions).                                       |
| `approvalId`     | string                            | Yes      | The pending approval request id (getAgentSession or listAgentApprovalsWaiting). |
| `decision`       | `"approve"`, `"deny"`, `"answer"` | Yes      | approve or deny a permission; answer (with the note) or deny a question.        |
| `note`           | string or null                    |          | A message to the agent with your answer; required to answer a question.         |

```json title="answerAgentApproval arguments"
{
  "organizationId": "acme",
  "sessionId": "09724085-1664-4183-a554-bacab2816579",
  "approvalId": "b51bae8b-100d-4cbd-a8e1-5f17fb649d88",
  "decision": "approve"
}
```

Claim agreed work, report progress, ask people, and run agent sessions on runners. Every tool takes `organizationId` (an id or slug from `listOrganizations`) unless it says otherwise. See the [overview](/reference/mcp) for errors, retries and what agents may not do.

### `listClaimableItems`

**List claimable work.** Query (read tokens too)

Work items an agent can claim now, in rank order: native delivery, not started, every blocking item done, nobody holding it, and allowed to start by the readiness policy (a specification Ready with its scope accepted; plain work covered by its parent specification's accepted scope, or selected into an unstarted status), and no pull request a person opened is linked to it (someone already does that work; a person may still start an agent on it). With `all`, also items that cannot be claimed yet, each with its `stage` (needs_agreement, blocked, claimed) and the reasons. External-delivery projects have no claimable work.

| Field            | Type    | Required | Description                                             |
| ---------------- | ------- | -------- | ------------------------------------------------------- |
| `organizationId` | string  | Yes      | Exact organization id or slug from listOrganizations.   |
| `projectId`      | string  |          |                                                         |
| `all`            | boolean |          | Include items that cannot be claimed yet, with reasons. |
| `limit`          | integer |          |                                                         |

### `claimItem`

**Claim work item.** Command · retry key `mutationId`

Agents: take a lease on one claimable work item (see listClaimableItems) and start it: the item moves to the project's first started status, attributed to you acting for your person. The lease lasts 15 minutes; keep it with renewClaim or reportProgress. Refused with kind `not_claimable` and the reasons when the item cannot be claimed, and `external_delivery` in projects delivered by an external tool. Exactly one live claim holds an item. Done follows from the Definition of Done (merged pull request, passing checks, sign-offs), never from your report.

| Field            | Type   | Required | Description                                                                    |
| ---------------- | ------ | -------- | ------------------------------------------------------------------------------ |
| `organizationId` | string | Yes      | Exact organization id or slug from listOrganizations.                          |
| `workItemId`     | string | Yes      |                                                                                |
| `mutationId`     | id     |          | Idempotency key. Retrying with the same value never applies the command twice. |

### `renewClaim`

**Renew claim.** Command · safe to repeat

The agent holding a claim extends its lease (default 15 minutes, 60 to 3600 seconds). Renew the lease while the claim is starting, active or waiting. A claim whose lease ran out is released by the next sweep and the item returns to the queue.

| Field            | Type    | Required | Description                                           |

| `organizationId` | string  | Yes      | Exact organization id or slug from listOrganizations. |
| `claimId`        | string  | Yes      | The claim (from claimItem or listClaims).             |
| `leaseSeconds`   | integer |          |                                                       |

### `releaseClaim`

**Release claim.** Command · retry key `mutationId` · destructive

Give a claimed item back without completing it, with an optional note. The item returns to the status it had before the claim started, unless someone moved it since. Allowed for the agent holding it, its person, project administrators and people who change properties in the project. Release while the claim is starting, active or waiting (it becomes released). A claim the dispatcher started that a person releases is not dispatched again until someone retries it.

### `askQuestion`

**Ask a question about the specification.** Command · retry key `mutationId`

The agent holding a claim asks people about the exact specification text it works against: a blocking discussion on the claimed item's specification (or its nearest specification ancestor's) anchored to `section` (a heading; empty for the whole text) and `quote` (text copied exactly from it). The item's reviewers are mentioned and notified, and the claim waits until a person resolves the discussion; you are told when it is resolved. A blocking question also blocks readiness, so related work waits too. Questions never change the specification. Ask people a question while the claim is active or waiting (it becomes waiting).

| Field            | Type    | Required | Description                                                                    |
| ---------------- | ------- | -------- | ------------------------------------------------------------------------------ |
| `organizationId` | string  | Yes      | Exact organization id or slug from listOrganizations.                          |
| `claimId`        | string  | Yes      | The claim (from claimItem or listClaims).                                      |
| `question`       | string  | Yes      |                                                                                |
| `section`        | string  | Yes      | Heading the question is about; an empty string for the whole text.             |
| `quote`          | string  |          | The exact specification text the question is about.                            |
| `occurrence`     | integer |          |                                                                                |
| `mutationId`     | id      |          | Idempotency key. Retrying with the same value never applies the command twice. |

### `startAgentSession`

**Start agent session.** Command · retry key `mutationId`

Ask a runner agent to work on a task. It is queued until a runner that may run the agent claims it. `prompt` says what to do; `workItemId` names the work item (its key becomes the default branch); `repositoryUrl` (https or ssh, no credentials) and `baseBranch` say where the code is. You need to own the agent or the agent must be shared. With `channelId` (and optionally `threadRootMessageId`) the session's live card, its approval requests and the agent's answers are posted in that thread, and replies there by you or the agent's owner steer it; you must be able to post in the channel. Retrying with the same `mutationId` returns the same session.

| Field                 | Type           | Required | Description                                                             |
| --------------------- | -------------- | -------- | ----------------------------------------------------------------------- |
| `organizationId`      | string         | Yes      | Exact organization id or slug from listOrganizations.                   |
| `agentId`             | string         | Yes      | Agent id (see listAgents).                                              |
| `prompt`              | string         | Yes      |                                                                         |
| `title`               | string         |          |                                                                         |
| `workItemId`          | string or null |          |                                                                         |
| `repositoryUrl`       | string or null |          |                                                                         |
| `baseBranch`          | string or null |          |                                                                         |
| `branch`              | string or null |          |                                                                         |
| `runnerId`            | string or null |          |                                                                         |

### `getInsights`

**Get insights.** Query (read tokens too)

Figures computed from the workspace, for questions about how work is going. topic `refinement`: specification refinement states, review progress, readiness checks and specifications that need attention. topic `delivery`: work by status, the active iteration's burndown and velocity, blocked or stalled work. topic `people`: workload per person and pending review requests. Narrow with projectId and teamId. The chat shows the result as cards; comment on it instead of repeating the numbers.

| Field            | Type                                     | Required | Description                                                                                                                                       |
| ---------------- | ---------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `organizationId` | string                                   | Yes      | Exact organization id or slug from listOrganizations.                                                                                             |
| `topic`          | `"refinement"`, `"delivery"`, `"people"` | Yes      | refinement (specification states, reviews, readiness), delivery (status, burndown, velocity, blocked work) or people (workload, pending reviews). |
| `projectId`      | string                                   |          | Project id (from getWorkspace).                                                                                                                   |
| `teamId`         | string                                   |          | Team id (from getWorkspace).                                                                                                                      |

```json title="getInsights arguments"
{
  "organizationId": "acme",
  "topic": "refinement"
}
```

### `createProject`

### `publishReadinessChecks`

**Publish Definition of Ready.** Command · retry key `mutationId` · **a person's decision**: refused to agents (the person decides in Project settings → Readiness)

Project administrators: publish the next version of the project's Definition of Ready. `rules` maps a work item type id to its complete list of checks; types left out use Lictory's defaults. Check kinds: specification, no_blocking_threads, reviews_requested, reviews_approved, children_ready (each at most once per type), section (`heading` must exist and not be empty), discipline_approval (`disciplineIds` approved the current revision), intelligence_review (an automated check, never an approval: the latest Lictory Intelligence review of the item analysed its current revision and found no finding at or above `severity`, `blocker` or `major`; at most once per type and only beside reviews_approved, discipline_approval or manual; a person can override it per revision with [signOffReadinessCheck](/reference/mcp/work-items#signoffreadinesscheck)) and manual (a named sign-off by someone in `disciplineIds`, or anyone holding a discipline when empty). `baseRevisionId` is the current version id from [getWorkspace](/reference/mcp/organization#getworkspace) (null while the project uses the defaults). Use [previewReadinessChecks](/reference/mcp/projects#previewreadinesschecks) first. Items that are ready or done keep the checks they met; every other item moves to the new checks and becomes ready when they pass.

| Field            | Type           | Required | Description                                                                                                                                                                           |
| ---------------- | -------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `organizationId` | string         | Yes      | Exact organization id or slug from listOrganizations.                                                                                                                                 |
| `mutationId`     | id             |          | Idempotency key. Retrying with the same value never applies the command twice.                                                                                                        |
| `projectId`      | string         | Yes      | Project id (from getWorkspace).                                                                                                                                                       |
| `baseRevisionId` | string or null | Yes      | The current revision id you read (getWorkItem). If the item changed since, the call is refused as a conflict with currentRevisionId, so nothing is applied to text you have not seen. |
| `rules`          | object         | Yes      | Checks per work item type id: \{ [typeId]: [checks] \}. Types left out use Lictory's defaults. Preview with previewReadinessChecks.                                                   |
| `summary`        | string         |          | Why the checks change, kept with the version.                                                                                                                                         |

```json title="publishReadinessChecks arguments"
{
  "organizationId": "acme",
  "mutationId": "6f1d2c3b-8a9e-4f70-b1c2-d3e4f5a6b7c8",
  "projectId": "3b0f6c1e-5d2a-4e8b-9f61-2a7c4d9e8b10",
  "baseRevisionId": "66fdac7b-2ec4-448a-a4d8-61e7fafcd9e5",
  "rules": {}
}
```

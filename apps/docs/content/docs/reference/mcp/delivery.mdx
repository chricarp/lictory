Hand work to Jira or another delivery tool, and follow what was exported. Every tool takes `organizationId` (an id or slug from `listOrganizations`) unless it says otherwise. See the [overview](/reference/mcp) for errors, retries and what agents may not do.

### `disconnectDelivery`

**Disconnect delivery tool.** Command · no retry key: read before repeating · destructive

Organization administrators: remove a Jira connection. Projects using it lose their hand-off target; existing links keep their history.

| Field            | Type   | Required | Description                                           |
| ---------------- | ------ | -------- | ----------------------------------------------------- |
| `organizationId` | string | Yes      | Exact organization id or slug from listOrganizations. |
| `connectionId`   | string | Yes      |                                                       |

### `previewDeliveryExport`

**Preview hand-off.** Query (read tokens too) · talks to an outside system

What handing off would do for each item (create, update, unchanged, or why it is skipped), including external edits that need overwrite confirmation. Changes nothing.

| Field            | Type           | Required | Description                                                                                                                                    |
| ---------------- | -------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `organizationId` | string         | Yes      | Exact organization id or slug from listOrganizations.                                                                                          |
| `rootId`         | string         |          | Hand off this item with its subtree (usually a ready Epic). Refused when the item itself is not ready.                                         |
| `itemIds`        | list of string |          | Or hand off these items, each with its subtree. Plain items (Tasks, Subtasks) go along under a parent in the same hand-off or already in Jira. |

### `publishDelivery`

**Hand off to delivery tool.** Command · no retry key: read before repeating · talks to an outside system · **a person's decision**: refused to agents (the person decides in The work item → Delivery → Export)

Hand ready work off to the project's Jira project: create or update issues. Only for projects delivered in Jira, and only when the person explicitly asked to hand off. Requires the hand-off capability in the project. Returns per-item results; retrying a failed item (itemIds) hands it off again with its subtree and never creates a second issue. Items edited externally are only overwritten when listed in overwriteItemIds.

| Field              | Type           | Required | Description                                                                                                                                    |
| ------------------ | -------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `organizationId`   | string         | Yes      | Exact organization id or slug from listOrganizations.                                                                                          |
| `rootId`           | string         |          | Hand off this item with its subtree (usually a ready Epic). Refused when the item itself is not ready.                                         |
| `itemIds`          | list of string |          | Or hand off these items, each with its subtree. Plain items (Tasks, Subtasks) go along under a parent in the same hand-off or already in Jira. |
| `overwriteItemIds` | list of string |          |                                                                                                                                                |

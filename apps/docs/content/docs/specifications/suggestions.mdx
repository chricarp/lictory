title: Suggest changes
description: How to suggest new wording for a passage, who accepts it, when a larger change goes to a branch, and what Lictory Intelligence proposes.
---

A comment says what is wrong; a suggestion says how to fix it. A suggestion
is proposed text that someone allowed to accept it accepts or rejects.
Accepting creates the next revision; nothing suggested becomes part of the
specification before that.

## Suggest new wording for a passage

<Steps>
<Step>

### Select the text

In the specification's reading view, select the passage you want to change
and choose **Suggest a change** in the toolbar that appears.

</Step>
<Step>

### Write what it should say

The suggestion opens beside the text with the passage filled in. Rewrite it,
add why if it helps, and check **Who accepts it**: Lictory asks the item's
owner or author by default, and you can pick anyone whose discipline both
edits specifications and reviews. Choose **Suggest**.

</Step>
<Step>

### The person asked accepts or rejects it

The passage is underlined in the text and the suggestion waits beside it,
with the words it changes marked. The review panel says how many suggestions
are waiting. The person asked chooses **Accept**, and the suggestion becomes
the next revision, or **Reject**. You can **Withdraw** your own.

</Step>
</Steps>

Anyone in the organization can suggest; you do not need to edit
specifications. Suggestions made by an agent through MCP appear the same way.

<Callout title="Comment or change?">
  If you are not sure what the text should say, start a
  [discussion](/specifications/discussions) instead. Suggest wording once the
  question is settled, so the change records an agreement rather than a guess.
</Callout>

## Larger changes

A passage with formatting or that spans several blocks, a change across the
document, or any change once the specification is ready (main is protected)
goes to the editor instead: **Suggest a change** then starts a branch named
`suggestion` with the passage selected, and the composer's **Larger change**
does the same. You commit there and open a pull request that the required
reviews approve. See [branches and pull requests](/specifications/branches).

## Changes proposed by Lictory Intelligence

When [Lictory Intelligence](/ai) is on, it can propose fixes, but always as
proposals:

- **From an item review.** Select the findings you agree with and choose
  **Open corrective pull request**. Lictory Intelligence applies exactly those
  edits, without another model call, on its own branch, one pull request per
  affected item, and invites you as a collaborator. Reviewers decide what
  merges. See [Lictory Intelligence reviews](/ai/reviews).
- **On a pull request.** A Lictory Intelligence review of a pull request can
  annotate a finding with a suggested edit. A collaborator on the source
  branch can choose **Commit suggestion** to commit it to the branch, where it
  is reviewed with the rest of the change.

Lictory Intelligence never writes main, approves, resolves discussions or
merges.

## What to watch for

- **Accepting is a new revision.** Like any change, it makes earlier
  approvals of the specification outdated and asks the reviews again
  ([approvals](/review/approvals)).
- **A suggestion written on an earlier revision** says so once the
  specification has moved on; its author can withdraw it and suggest again.
- **Once the specification is ready**, suggestions can no longer be accepted
  into it: changes go through a branch and a reviewed pull request.

## Tips

- Suggest the smallest change that settles the point. Focused suggestions are
  decided faster.
- Add why when the change answers a discussion, so the person accepting it
  sees the reason beside the words.

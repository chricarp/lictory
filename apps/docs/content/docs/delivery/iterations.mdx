---
title: Sprints and cycles
description: Plan work into time-boxes, start and complete sprints by hand or let cycles run on a schedule, and keep each iteration's notes with it.
---

An **iteration** is a time-box of planned work. A native project plans in
one of three ways:

- **None**: a ranked backlog, without time-boxes.
- **Sprints**: you create, start and complete each one by hand.
- **Cycles**: Lictory schedules, starts and completes them from a length and
  a start day, and rolls unfinished work into the next one.

One iteration per project is active at a time.

## Set up planning

Project administrators choose in **Project settings → Planning**:

- **Iterations**: **None**, **Sprints** or **Cycles**;
- **Length**: 1, 2, 3, 4, 6 or 8 weeks;
- for cycles, **Starts on** (the weekday a cycle begins) and **Upcoming
  cycles** (how many planned cycles to keep ahead of the active one);
- **Estimates**: the [estimate scale](/delivery/backlog#estimates).

## Run a sprint

<Steps>
<Step>

### Create it

On the backlog, choose **New sprint**. It starts when the last open sprint
ends (or today) and lasts the project's length. Sprints are numbered
(**Sprint 1**, **Sprint 2**); **Edit** sets a name and a **Sprint goal**.

</Step>
<Step>

### Plan it

Drag work from the backlog into the sprint. Its item count and points sit
next to the team's recent velocity.

</Step>
<Step>

### Start it

Choose **Start**. Only one sprint can be active at a time. The board then
shows the active sprint by default.

</Step>
<Step>

### Complete it

Choose **Complete** and pick where unfinished work goes: the next planned
sprint, or **Backlog**. The sprint's report is frozen at that moment;
**View report** opens it.

</Step>
</Steps>

Starting and completing need project administration or a discipline that
can **Change properties**.

## Let cycles run

With **Cycles**, Lictory keeps one cycle active and the chosen number of
upcoming cycles planned. When a cycle ends, it is completed and its
unfinished work moves into the next one. The schedule is checked every few
minutes, so the switch can lag a cycle's end by a few minutes.

Plan by dragging work from the backlog into an upcoming cycle.

## Iteration notes

Each iteration can keep its own [context pages](/knowledge/context-pages):
the goal, the plan, the retrospective.

<Steps>
<Step>

### Open the iteration's context

Use **Context** on the iteration's backlog row, the board's **Context**
while viewing the sprint, or the **Pages** section of its report.

</Step>
<Step>

### Create iteration notes

![Notes for Sprint 1 opened from the sprint’s Context: a new page with the goal, a live list of the iteration’s work, risks, notes and a retrospective, the Space to create it in and its Title, with Back and Create and open](/screenshots/delivery-iteration-notes-dialog.webp)

Choose **Create iteration notes**. Pick the **Space** (spaces you can edit,
the project's own first) and a **Title** (`Sprint 1 notes` by default), then
**Create and open**.

</Step>
<Step>

### Fill it in

The page has a **Goal** (the sprint goal, if any), a live **Work** list of
the iteration's items, **Risks**, **Notes**, a **Retrospective** and
**Follow-ups**. Its first version is published and linked to the iteration.

</Step>
</Steps>

![Sprint 1 notes in the Payments space: the Goal, the live Work list showing each item's current status, and the Risks section waiting to be filled](/screenshots/delivery-iteration-notes.webp)

Each reader sees the items' current status, and only the items they may
see. Otherwise it is an ordinary [page](/spaces/pages) of the space.

Completed iterations can still get notes, from the **Pages** section of
their report, so the retrospective can come after the sprint closes.

## What to watch for

- **Completed iterations are history.** They cannot be renamed or planned
  into, and their reports do not change.
- **Planning is tentative.** Putting an item in a sprint does not accept it
  for delivery. See [ready is not accepted](/delivery#ready-is-not-accepted).
- **No space you can edit, no notes.** **Create iteration notes** needs edit
  access to a space. Ask for it, or [create a space](/spaces/create) for the
  project.
- **Creating notes is safe to retry.** The page and its link are created
  together or not at all; retrying never creates a second page.
- **Jira projects have no iterations.** Sprints are planned in Jira. Switch
  to Jira only after completing the active iteration.
- **Templates in a space don't link.** A page created in a space from the
  **Iteration notes** template shows the iteration's work but is not one of
  its context pages. Add it from **Context → Add page**.

## Tips

- Create the notes page the day the sprint starts.
- Turn retrospective follow-ups into work items by selecting the text on the
  page. See [work in pages](/knowledge/in-pages).
- Write a sprint goal: it shows on the backlog, the report and the notes
  page.

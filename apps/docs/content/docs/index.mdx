Lictory is the control plane of a software factory: one self-hosted product
where a software team and its agents talk, agree on what to build, plan it,
write and review the code and ship it. People make the decisions; agents do
much of the work in between, each with an owner who is accountable for it.

Every piece of work follows one loop. A conversation in a
[channel](/channels) is promoted into a proposal. The proposal becomes a
specification that is drafted, reviewed and approved the way code changes are,
so a team goes from “_Product wants to build this_” to “_Engineering can safely
commit to building this_” without a meeting for every requirement. Agents on
[runners you control](/factory/runners) then claim the agreed work, open pull
requests on your [code host](/integrations/code-hosts) and answer review, and
an item is done when the evidence says so: merged code, passing checks and the
project's Definition of Done.

## Requirements, reviewed like code

A specification in Lictory is not a document with comments. It has
[revisions](/specifications/history), a [live draft](/specifications/live-drafts)
people edit together, reviewers, [discussions](/specifications/discussions)
anchored to the text, proposed changes on [branches](/specifications/branches),
[approvals that belong to the revision they reviewed](/review/approvals), and
[readiness checks](/review/readiness) that work like CI for requirements. At
any time you can see what changed, who changed it, who approved which
revision and what is still unresolved.

Product, Engineering, QA and any other discipline a project configures take
part as equals: each reviews the concerns it owns. Lictory Intelligence can
point out gaps, contradictions and missing scenarios and propose changes, but
people decide what becomes part of the specification. Lictory works fully
without AI.

## Agents that do the work, people who decide

The [Factory](/factory) runs coding agents (Claude Code, Codex, OpenCode,
Gemini CLI or Lictory's built-in agent) on runners you control. Each agent has
a name, an owner and a scope, acts with its owner's permissions and is shown as
acting via that person. A project's [autonomy policy](/factory/autonomy)
decides how much happens by itself: agents help when asked (Assist), take
ready work and open pull requests that people merge (Build), or Lictory also
merges an agent's pull request when every required check passes (Autopilot).
Specification approvals, accepted scope and resolved discussions always stay a
person's act. Text is never permission: a message, issue or model output
cannot authorize anything.

## Two ways to deliver

Every project chooses its delivery mode. The refinement workflow is the same
in both.

| Mode                 | Refinement | Delivery                                                               |
| -------------------- | ---------- | ---------------------------------------------------------------------- |
| **Native (Lictory)** | Lictory    | Lictory: work item types, workflows, board, backlog, sprints or cycles |
| **External (Jira)**  | Lictory    | Jira: ready work is handed off, Jira's status is read back             |

Exactly one system owns delivery for a project's work, so nothing is tracked
twice. See [delivery](/delivery).

## Knowledge next to the work

[Spaces](/spaces) hold the pages a team writes together: runbooks,
architecture notes, decision records, how the team works. Pages and work are
linked both ways: a specification cites the page version it relies on, a
page mentions and lists live work, a work item can start from a passage of a
page, and delivered work can propose the page update it needs. Each item's
[Knowledge](/knowledge) shows the pages about it, and [search](/search) finds
both.

## Work from your terminal or editor

Connect a coding agent through [MCP](/integrations/agents) to read specifications,
inspect discussions and propose changes on branches with your permissions.
People still decide what gets approved, merged or handed off. For installing
and operating a server, use the guided [lictory CLI](/self-hosting/terminal).

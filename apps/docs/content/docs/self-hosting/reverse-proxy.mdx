---
title: Reverse proxy and TLS
description: Run Lictory behind nginx, Traefik or an ingress, with an internal CA, or on plain HTTP for an evaluation.
---

The bundled gateway is always the entry point of an installation: it routes
the API, server-sent events, AI streams, the realtime and live editing
WebSockets and the application's assets, sets the security headers and checks the WebSocket
`Origin`. What varies is who terminates TLS.

| Setup                             | TLS terminated by        | Settings                                                       |
| --------------------------------- | ------------------------ | -------------------------------------------------------------- |
| Standalone (default)              | The gateway, public ACME | `APP_HOST`, `ACME_EMAIL`                                       |
| Internal CA                       | The gateway              | `CADDY_GLOBAL_OPTIONS`                                         |
| Existing reverse proxy or ingress | Your proxy               | `PROXY_SCHEME=http`, `PLATFORM_URL`, bindings, trusted proxies |
| Plain HTTP (evaluation only)      | Nobody                   | `PROXY_SCHEME=http`, `PLATFORM_URL=http://…`                   |

The installer sets each of these up (`--tls acme|internal|proxy|http`); the
settings below are what it writes, for reference or a hand-made `.env`.

## Behind an existing reverse proxy

```sh
sudo lictory install --tls proxy --host lictory.example.com \
  --http-port 8080 --bind 127.0.0.1 --public-url https://lictory.example.com
```

`lictory doctor` then prints the address your proxy connects from; set it with
`sudo lictory install --trusted-proxies <address>`.

Run the gateway as plain HTTP on a private address and let your proxy
terminate TLS:

```sh
# The Host header your proxy forwards.
APP_HOST=lictory.example.com
PLATFORM_URL=https://lictory.example.com
PROXY_SCHEME=http
HTTP_PORT=8080
# Or a private address your proxy reaches.
HTTP_BINDING=127.0.0.1:8080:80
# Unused, but kept off the public 443.
HTTPS_BINDING=127.0.0.1:8443:443
# The address your proxy connects from.
CADDY_TRUSTED_PROXIES=172.18.0.1
# Required, unused over HTTP.
ACME_EMAIL=ops@example.com
```

Your proxy must:

- forward the original `Host`;
- pass WebSocket upgrades for `/zero/*` (realtime updates) and
  `/collaboration` (live editing of pages in Spaces) with the browser's
  `Origin`, the session cookie and the path unchanged;
- not buffer responses (at least `/api/` and `/relay/`): server-sent events
  and AI answers stream;
- allow at least 300 seconds for reading responses and for idle connections;
- accept request bodies up to 12 MB;
- append the client address to `X-Forwarded-For` (or overwrite it), with
  `CADDY_TRUSTED_PROXIES` set to the address(es) it connects from. Otherwise
  every user shares one sign-in rate limit. Never trust all private ranges.

Do not publish the API, zero-cache, the collaboration service or PostgreSQL
directly, and do not strip the gateway's security headers.

The nginx example below sends every path, both WebSockets included, through
one `location /`. If you split locations, give `/zero/` and `/collaboration`
the same upgrade headers, no buffering and long timeouts.

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 443 ssl;
    http2 on;
    server_name lictory.example.com;
    ssl_certificate     /etc/nginx/tls/lictory.example.com.crt;
    ssl_certificate_key /etc/nginx/tls/lictory.example.com.key;
    client_max_body_size 12m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

Traefik and Kubernetes ingress examples are in the
[reverse proxy runbook](https://github.com/chricarp/lictory/blob/main/docs/operations/reverse-proxy.md).

After changing the proxy, check sign-in, live updates between two browsers,
and editing one page of a space from two browsers: both editors should see
each other's typing and **Saved**.

## Internal CA

The gateway can obtain certificates from an internal ACME CA (step-ca, Vault,
AD CS with ACME):

```sh
sudo lictory install --tls internal --host lictory.internal.example \
  --acme-ca https://ca.internal.example/acme/acme/directory --acme-email ops@example.com
```

which writes:

```sh
CADDY_GLOBAL_OPTIONS=acme_ca https://ca.internal.example/acme/acme/directory
```

Without `--acme-ca` (`CADDY_GLOBAL_OPTIONS=local_certs`) the gateway becomes
its own CA. Distribute its root certificate to your users' trust stores:

```sh
sudo /srv/lictory/bin/lictory-compose production exec -T proxy \
  cat /data/caddy/pki/authorities/local/root.crt > lictory-root.crt
```

To use existing
certificate files, terminate TLS in a reverse proxy as above.

## Plain HTTP

For a quick evaluation on `localhost` only:

```sh
sudo lictory install --tls http --host localhost --http-port 8080
```

which writes:

```sh
APP_HOST=localhost
PLATFORM_URL=http://localhost:8080
PROXY_SCHEME=http
HTTP_PORT=8080
HTTP_BINDING=127.0.0.1:8080:80
HTTPS_BINDING=127.0.0.1:8443:443
```

Over plain HTTP, session cookies are not `Secure`: anyone who can observe
the network can read sessions and documents. Browsers also treat any host
other than `localhost` as insecure and disable features the application
needs. Use HTTPS for anything beyond a local trial.

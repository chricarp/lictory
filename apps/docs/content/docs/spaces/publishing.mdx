---
title: Publishing
description: How a live draft becomes the version everyone reads, directly or through approved pull requests.
---

Readers see a page's **published version**, the latest on its main line.
The space's publishing policy decides how a live draft gets there.

| Policy               | How changes are published                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Direct** (default) | Editors edit the page's live draft together and **Publish** it. Branches and pull requests remain available for bigger changes.                  |
| **Reviewed**         | The published page is protected: it has no live draft. Changes are proposed on a branch and published only when an approved pull request merges. |

Choose Direct for knowledge kept current day to day (runbooks, onboarding,
team notes), and Reviewed where a change must be agreed first (policies,
architecture decisions, anything others rely on). Someone working alone
needs Direct: nobody can approve their own changes.

Publishing a page is unrelated to handing work items off to Jira.

## Direct spaces

<DirectPublishing />

<Steps>
<Step>

**Edit.** Open the live draft with **Edit** and write
([writing together](/spaces/editing)).

</Step>
<Step>

**Publish.** Choose **Publish**, add an optional **Message** (_What
changed?_) and choose **Publish now**, or press Mod+Enter.

</Step>
<Step>

**Done.** Lictory waits until your edits are **Saved**, then turns what the
server stored into the next version (_Published version 3_), or says _No
changes to publish_.

</Step>
</Steps>

Publish seals the draft, title included, as stored when you published;
later edits stay **Unpublished changes**. Everyone who typed since the last
version is recorded as a contributor, next to the publisher.

Everyone with **edit** access can publish. Open blocking comments do not stop
**Publish** in a Direct space; they block merging pull requests
([comments](/spaces/comments#blocking-comments)).

## What readers see

![A published page in dark mode: “Published version 1 by Maria Chen” under the title and Edit unpublished draft instead of Edit, because the live draft holds changes nobody has published yet](/screenshots/spaces-unpublished-draft-dark.webp)

- _Published version N · by … · when_ under the title (_Published vN_ on a
  phone; tap for details). In a Reviewed space it is marked **Approved**,
  naming who approved it.
- **Edit unpublished draft** instead of **Edit** when the live draft has
  unpublished changes. Readers without edit access never see a draft.
- [Search](/search), [Litto](/ai/litto) and agents read only versions (the
  published one, or an earlier one on request), never a live draft. Work
  items link to what a page published
  ([knowledge links](/knowledge#references-follow-published-versions)).

Earlier versions are in the page's [history](/spaces/history), or behind the
_based on vN_ link in the editor.

## Reviewed spaces

In a Reviewed space main has no live draft. Editors see _Changes to this
page are reviewed._ with **Start a branch**:

<Steps>
<Step>

**Start a branch.** Keep or change the suggested name (such as
`maria/Payments-service`) and choose **Start branch**. The page switches to
your branch's live draft.

</Step>
<Step>

**Write and send for review.** Edit the draft, alone or with
[collaborators](/spaces/branches#collaborators). **Commit**, choose the
reviewer and **Commit and send for review** to commit and open a pull
request into main asking them. **Commit only** asks nobody yet.

</Step>
<Step>

**Merge.** When every required reviewer approves the current result and the
merge checks pass, **Merge pull request** publishes it. See
[branches and pull requests](/spaces/branches).

</Step>
</Steps>

<ReviewedChange />

A version merged in a Reviewed space is marked **Approved** with its
approvers. In a Direct space the same people are recorded as **Reviewed
by**, never as an approval.

## Change the publishing policy

A space's [administrators](/spaces/access#administrators) change the policy
in **Space settings → Location & publishing → Publishing**.

- **Direct → Reviewed** is refused while any page has unpublished changes.
  Publish them first; a policy change never throws away draft text.
- **Reviewed → Direct** reopens each page's live draft at its published
  version.

Branches, pull requests, reviews and versions are unaffected.

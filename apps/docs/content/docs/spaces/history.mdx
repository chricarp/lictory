---
title: Versions and history
description: Compare any two versions of a page word by word, read an old one as it was, and restore it as a new version.
---

A **version** is an immutable snapshot of a page's title and content, with a
message, who published or committed it and who contributed. Editing,
restoring and merging never change it, so _what did this page say when we
approved it?_ has an answer months later.

## Open the history

**More page actions** (**⋯**) → **Version history** has three views:

- **Versions**: the page's versions, newest first;
- **Branches**: the page's branches ([branches](/spaces/branches));
- **Pull requests**: proposed changes and their reviews
  ([pull requests](/spaces/branches#pull-requests)).

**Open published page** goes back to the page.

## The version list

Each version shows its number (**v1**, **v2**…), message (or title), author,
time and _With …_ other contributors. Badges mark the **Published** version
and merges with reviews: **Approved** in a Reviewed space, **Reviewed** in a
Direct one.

The list follows one line: main, or the branch chosen in the branch
switcher. A pull request merged into main is one version on main; the
branch's commits stay in the branch's history.

## Compare two versions

Select a version to compare it with the one before; **Compare with** picks
any other version of the line.

- The summary counts the **blocks changed**. A block is a paragraph, heading,
  list, table, quote or code block.
- Each change is labelled **Added**, **Removed**, **Edited**, **Moved ·
  position changed** or **Moved and edited**.
- An edited block shows **Before** and **After** side by side, with the
  changed words struck out in Before and marked in After.
- Runs of **unchanged blocks** fold into one line; open a fold for context.
- A changed title is compared word by word above the content.

## Read an old version

**Preview this version** renders the version as published, with chips and
page links resolved for you now. Work lists show today's items
([work lists](/spaces/blocks#live-work-lists)). **View changes** returns to
the comparison. Each version has its own address to link to, and a
specification can cite it
([pinned citations](/knowledge/in-work#pinned-citations-in-specifications)).

## Restore a version

People who can edit a line choose **Restore this version** on the selected
version.

This creates a **new version** with the old title and content on the line
you are viewing (_Restore to main_, or to the branch). Everything after it
stays in the history, so restoring again undoes it. A version identical to
the latest says _Nothing to restore_.

A restore on main is published, so the page's [links to work](/knowledge)
follow it: an item mention the restored version lacks stops showing on that
item.

Restoring also replaces the line's live draft:

- Open editors move to the new content; their unsaved text is kept to
  reinsert or copy
  ([when the draft is replaced](/spaces/editing#when-the-draft-is-replaced)).
- With unpublished or uncommitted changes, **Restore version** needs
  **Discard live changes on this branch** ticked. Publish or commit them
  first to keep them in history.

In a Reviewed space main changes only through pull requests: start a branch
from the old version (**Branches → New branch → Start from**) and propose
it.

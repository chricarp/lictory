title: Page templates

A template gives a new page headings, a short prompt under each, and,
where it helps, a live list of related work. Once created, the page is an
ordinary page with no link back to the template.

![The New page dialog: a Title field and Start from with Blank and six templates, each with a one-line description, and Create page](/screenshots/spaces-page-templates.webp)

## When to use it

When readers look for the same sections every time: what a feature must do,
how a service is designed, what to do when an alert fires, why a decision
was made. Otherwise start from **Blank**.

## Create a page from a template

<Steps>
<Step>

**Open New page.** **New page** on the space's home, the **+** at the top of
the page tree, or **New subpage** in a page's actions
([create a page](/spaces/pages#create-a-page)). Needs edit access.

</Step>
<Step>

**Name it and choose the template.** Type a **Title**, then pick one under
**Start from**.

</Step>
<Step>

**Choose an iteration** (iteration notes and retrospectives in a project
space). The optional **Iteration** field offers the project's uncompleted
iterations, the active one preselected. **No live list** leaves the list
out.

</Step>
<Step>

**Create page.** The template is the page's first, published version. Edit
it with **Edit** in a Direct space or **Start a branch** in a Reviewed one
([publishing](/spaces/publishing)).

</Step>
</Steps>

## The templates

| Template                 | Sections                                                                                                               | Live work list                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **Blank**                | An empty page                                                                                                          | None                                                             |
| **Product requirements** | Problem, Goals, Non-goals, Requirements, Open questions                                                                | **Related work**: the items the page mentions                    |
| **Design doc**           | Context, Proposal, Alternatives considered, Risks and failure behavior, Rollout, Decisions                             | **Related work**: the items the page mentions                    |
| **Runbook**              | When to use this runbook, Before you start (tasks: access you need, who to tell), Steps, Verify, Roll back, Escalation | None                                                             |
| **Decision record**      | Status (_Proposed_), Context, Decision, Options considered, Consequences                                               | None                                                             |
| **Retrospective**        | What went well, What did not go well, What we learned, Actions                                                         | **Work in the iteration**, when you chose an iteration           |
| **Iteration notes**      | Goal, Work, Risks, Notes, Retrospective (What went well, What to change), Follow-ups                                   | The iteration's work under **Work**, when you chose an iteration |

An italic prompt under each heading says what belongs there (_Describe the
expected behavior, including failure cases._); replace it as you write. The
design doc and decision record prompts suggest `/` → **Decision** to show a
decision recorded on a work item; the requirements prompt suggests creating
a work item from a selected requirement.

## Iteration notes from the board or backlog

**Create iteration notes** in an iteration's context pages (on the board,
the backlog or the iteration report) creates the page from this template in
a space you can edit, with the goal filled in, and keeps it as the
iteration's context page. See
[context pages](/knowledge/context-pages#create-iteration-notes).

## What to watch for

- **The first version is published at once**, also in a Reviewed space.
  Later changes follow the space's publishing policy.
- **Live lists show today's work.** A work list stores its query, not its
  items, so an old version shows the items as they are now. See
  [live work lists](/spaces/blocks#live-work-lists).
- **The iteration list needs a project.** Only pages in project or team
  spaces offer **Iteration**, for uncompleted iterations. Without it, add a
  list later with `/` → **Work list**.
- **Templates are fixed.** You cannot add or change templates. To reuse your
  own structure, keep an example page and copy from it.

## Tips

- Write a runbook from the **Runbook** template and attach it to the work
  items it supports, with the purpose **Runbook**
  ([attach a page](/knowledge/in-work#attach-a-page)).
- Start product requirements in a page when the problem spans several items,
  then **Create work item** from each requirement: every item keeps a quote
  of the exact version it came from.
- Give each sprint a notes page from **Create iteration notes**: goal, live
  work and retrospective in one place.

title: Agents and MCP
description: What an agent connected through MCP can read and propose in Spaces, and the decisions that stay with people.
---

Agents connected through [MCP](/integrations/agents) work in Spaces with
exactly the space access of the person whose token they use.

## What an agent can read

- the spaces you can read and your level in each (`listSpaces`), and a
  space's page tree (`listPages`);
- a page's published title and content as Markdown, or any earlier version
  (`getPage`), never an unpublished live draft;
- a page's history and branches, and what changed between two versions
  (`listPageCommits`, `diffPageCommits`);
- what merging a pull request would produce right now, with any conflicts
  (`previewPageMerge`);
- a page's discussions (`listPageThreads`);
- the work a page knows about: items it mentions, items whose
  specifications cite it or that it is attached to, items created from it,
  and the projects, teams and iterations that keep it as context
  (`listPageWork`, `listReferencesTo`);
- published pages that match a phrase (`searchKnowledge`), and published
  pages among the agreements and decisions that answer a question
  (`searchProductKnowledge`), each with the exact version to cite.

See the full list in [AI agents and MCP](/integrations/agents#spaces), and
links between pages and work in
[find and cite knowledge](/integrations/agents#find-and-cite-knowledge).

## How an agent changes a page

Agents cannot type into live drafts. They **propose** a new version:
`proposePageChange` takes the page as Markdown and, in one step, branches
from the published version, commits the content and opens a pull request
into main for people to review
([branches and pull requests](/spaces/branches)).

To document a work item, the agent passes the item's revision as `origin`,
like **Propose page update**; the item then lists the proposal in its
Knowledge section ([knowledge in work items](/knowledge/in-work)).

As your access allows, an agent can also:

- start and reply to discussions on a page or a quoted passage;
- create spaces and pages, move or archive pages;
- start branches, open pull requests, request reviews and resolve conflicts
  on a branch;
- attach a page to a work item, keep it as context of a project, team or
  iteration, and create a work item from a passage of a published page.

Ask, for example:

> Read the refund runbook in the Payments space and PAY-142's current
> specification. Propose an updated runbook that matches the new timeout
> behavior, open a pull request and ask Dev for a review. Do not merge it.

## What stays with people

The server refuses these to an agent's token (a personal access token can
make them when you explicitly ask), and Litto asks you to confirm first:

- publishing a live draft (agents never type into one);
- approving or requesting changes on a pull request, and merging it;
- resolving, reopening or marking a discussion blocking.

An agent acting for you counts as you: you cannot approve a change your agent
proposed, and several agents on one person's token are not independent
reviewers.

The MCP instruction guides the agent but is not a lock: a read/write token
can do anything your access allows. Use a read-only token for an agent that
should only read.

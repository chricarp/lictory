---
title: Runners
description: Install lictory-runner on a server, VPS, laptop or Mac, register it with a one-time token and keep it running as a service.
---

A **runner** is a machine that runs agent sessions. It connects out to
Lictory over HTTPS, so it needs no open port and works behind NAT, proxies
and firewalls that allow outbound HTTPS. Each session works in its own git
worktree; a runner can also run each session in a Docker container.

- An **organization runner** runs any agent of the organization. An
  organization administrator adds it.
- A **personal runner** runs only your own agents, for example on your
  laptop. Any member can add one.

## Add a runner

1. Open **Factory → Runners** and choose **Add runner**.
2. Choose an organization or a personal runner and **Create registration
   token**. The token works once and expires after an hour.
3. Copy the commands for your system and run them on the machine. They
   download `lictory-runner`, register it and install it as a service:

```sh
lictory-runner register --url https://lictory.example.com --token lrt_…
lictory-runner install-service --enable
```

The runner appears in the list as soon as it registers and shows **Online**
while it is connected.

Install the harnesses its agents use on the same machine: Claude Code
(`claude`) or Codex (`codex`), signed in with your own subscription or API
key. The built-in harness needs nothing on the machine: it uses the
organization's Lictory Intelligence model through the server.

## Commands

| Command                          | What it does                                                          |
| -------------------------------- | --------------------------------------------------------------------- |
| `lictory-runner register`        | Exchanges a registration token for the runner's credential            |
| `lictory-runner start`           | Connects and runs sessions until stopped (Ctrl-C hands them back)     |
| `lictory-runner status`          | Shows whether the runner is running and what it is working on         |
| `lictory-runner doctor`          | Checks the server, the credential, git, harnesses, Docker and clock   |
| `lictory-runner install-service` | A systemd unit (Linux) or launchd agent (macOS); `--enable` starts it |

`register` accepts `--name`, `--max-sessions <n>` (default 2),
`--isolation host|container` and `--label <label>`. On Linux a user service
stops when you log out unless lingering is on (`loginctl enable-linger`);
`--system` installs a system service instead. On Windows,
`install-service` prints the Task Scheduler commands.

The configuration and credential are in `~/.config/lictory-runner` on Linux,
`~/Library/Application Support/lictory-runner` on macOS and
`%APPDATA%\lictory-runner` on Windows (`LICTORY_RUNNER_HOME` overrides
it), readable only by your account. `config.json` also holds
`claudePermissionMode` (what Claude Code may do without asking, default
`acceptEdits`), `codexSandbox` (default `workspace-write`),
`containerImage` and `keepWorktrees`.

## Revoke a runner

Choose the trash icon next to the runner. Its credential stops working at
once and the sessions it was running return to the queue. A personal runner
also stops working when its owner leaves the organization.

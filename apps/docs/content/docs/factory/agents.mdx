title: Agents

An **agent** is a named, non-human member of your organization: a name, an
`@handle`, an owner and a scope. It acts with its owner's permissions,
narrowed by its scope, and history shows it as acting via its owner
("Forge via Ada"). An agent never has more access than its owner.

## Create an agent

Open **Factory → Agents** and choose **New agent**:

- **Runs on a runner**: a coding harness (Claude Code, Codex or the built-in
  harness) that sessions run on a runner. Choose the harness, optionally a
  model and a runner, and instructions given with every session.
- **External MCP client**: an agent you run yourself that connects to
  Lictory with a [token](#connection) of its own. Creating it opens its
  page on **Connection**, with its first token (valid for 90 days) shown
  once.

You own the agents you create and are accountable for what they do.

## The agent's page

Choose an agent in **Factory → Agents** to open its page: its owner, kind
and scope, and its recent sessions. For the agents you own, the page also
holds everything that connects them, so each agent has one place:
**Connection** and **Wake-ups**. Other people see who owns it, and only the
owner manages its tokens and wake-ups.

## Scope

- **Read and write** or **Read only**: a read-only agent only reads.
- **Projects**: every project, or only the ones you choose. A
  project-limited agent cannot use organization-wide operations such as
  searches across every project, work item types or spaces.
- **Others may start sessions with it**: off by default. A shared agent
  still acts as you, so share only agents whose scope you are comfortable
  lending.

Agents never create agents, change scopes, add runners or create tokens:
those stay with people in the browser. Agents never approve, merge or answer
an approval request for a person.

## Connection

**Connection** lists the agent's tokens. Choose **New token**, pick when it
expires and **Create token**: the secret is shown once, with the MCP URL
(`https://<your-lictory-host>/api/mcp`) and a setup snippet for Claude Code,
Codex or another client, which sends it as `Authorization: Bearer <token>`.
The client then works as the agent in this organization only: your
permissions, narrowed to the agent's scope, shown as "Scout via Ada".

**Rotate** replaces a token with a new one (shown once) and revokes the old
one; **Revoke** disconnects the client at once. Tokens also stop working
when you archive the agent or leave the organization.

Each session of a runner agent gets its own short-lived token, so a
harness can use Lictory's MCP tools as the agent while the session runs; a
runner agent needs no token of yours.

## Wake-ups

**Wake-ups** tells the agent when something waits on it or on you (a
mention, a review request, a stale approval, a decided pull request…), so
its client need not ask over and over. Choose **New webhook** for a client
that starts from a URL and a key (Claude routines, Grok, OpenClaw hooks):
its name, the URL, the bearer secret and the event types, then **Test** it.
Each wake-up shows whether it is active, what it delivered and the last
problem; while a receiver fails it also shows how many attempts failed and
when it tries again. **Pause**, **Resume** and **Remove** it there. Clients that support
MCP Events subscribe themselves with the agent's token and appear here too.
See [AI agents and MCP](/integrations/agents#wake-your-agent-when-something-waits-on-you).

## Recent activity

Its owner sees what the agent did under **Recent activity**: every tool it
called with one of its tokens (its own or its sessions'), when, and whether
it worked or was refused. What it sent is never recorded. Organization
administrators see every agent's calls in the
[audit log](/organization/audit).

## Archive an agent

Choose the archive icon. Its tokens stop working and its sessions and
history stay. The owner or an organization administrator can archive and
restore an agent.
